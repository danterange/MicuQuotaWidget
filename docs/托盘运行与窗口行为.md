# 托盘运行与窗口行为

## 目标

MicuQuotaWidget 是桌面悬浮余额卡片，而不是任务栏应用。主窗口启动时仍显示在桌面，但 `ShowInTaskbar=false`；Windows 通知区域中的绿色 Micu 图标是后台入口和唯一的显式退出入口。

## 行为约定

| 用户动作 | 结果 |
| --- | --- |
| 点击主卡片右上角隐藏图标、Alt+F4 或系统关闭请求 | 主卡片隐藏到通知区域；10 秒轮询继续，任务栏不出现窗口按钮。 |
| 双击托盘图标或选择“显示 / 隐藏小组件” | 切换卡片可见性；恢复时回到 `Normal` 状态并激活窗口。 |
| 选择“立即刷新余额” | 复用主窗口既有 `RefreshCommand`，不创建第二条请求或第二份 API Key。 |
| 选择“切换窗口置顶” | 复用既有 `ToggleTopmostCommand`，与 `Ctrl+T` 和卡片开关保持一致。 |
| 选择“打开设置” | 先显示主卡片，再打开唯一的 owned `SettingsWindow`；设置窗口同样不显示在任务栏。 |
| 选择“退出 MicuQuotaWidget” | 唯一允许真实关闭窗口、停止轮询、释放 `NotifyIcon` 和 `HttpClient` 的路径。 |

## 图标与资源

托盘图标由 `TrayIconService` 使用 .NET 内置 `System.Drawing` 在运行时生成 32px 绿色几何 Micu 标记，再克隆为独立 `HICON`。这避免第三方依赖和外部图片文件；生成的原始 Win32 句柄会立即释放，应用退出时图标和菜单也会幂等释放。

图标 tooltip 固定为“`Micu 余额小组件`”，不得包含余额、API Key、用户名、原始错误或任何私人信息。

## DPI 与验收

应用 manifest 声明 `PerMonitorV2` DPI awareness，以避免在不同显示器缩放下将紧凑卡片或设置窗口裁切。自动 WPF 测试覆盖尺寸、无任务栏和隐藏/恢复生命周期；实际 Explorer 通知区域行为仍需按 [UI 测试](UI测试.md) 在 100% 与 150% 缩放下人工核验。
